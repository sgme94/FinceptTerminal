路线 B：Fincept Shell + Polymarket 产品原型

三种方式都保留 Fincept 登录态终端骨架，但 Polymarket 改造深度不同。点击你倾向的方向，或直接在终端回复。

B1: Dashboard First

Polymarket event ticker: politics / macro / crypto / sports

paper/live switch, capital, exposure, active markets, order queue

Agent Composer

B1 Dashboard 控制台优先

最快形成可用管理页。Dashboard 直接变成 Bot Control Center，Markets/News/Agents/Fund Managers 逐步改造。

B2: Four Core Workspaces
F1 OVERVIEW | F2 MARKETS | F3 SIGNALS | F4 RISK | F5 NEWS | F6 DATA | F7 AGENTS | F8 AUDIT
Market probability ticker + PnL ticker
Overview: bot health + PnL
Markets: order book + chart
Signals: model/agent score
Risk: exposure + limits

B2 四工作区重组

把 Fincept 入口重新归并为 Overview、Markets、Signals、Risk、News/Data、Agents、Audit。更适合 Polymarket bot 的真实运营。

B3: Agentic Arena
F1 DASH | F2 MKTS | F3 AGENTS | F4 ARENA | F5 NEWS | F6 ECON | F7 RISK | F8 HIST
Live agent cycle ticker
Agentic World
event sentinels, claims, evidence, dissent
Fund Manager Arena
strategy leaderboard, NAV, drawdown, trades

B3 Agent 竞技场优先

突出多 Agent 研究和多策略排名，适合研究展示；但 Bot 执行控制会分散，需要额外设计运营面板。

我的推荐：B2

  • 比 B1 更贴近自动交易平台的真实操作路径。
  • 比 B3 更容易落到现有 paper bot、风险和审计模块。
  • 仍能复用 Fincept 的 Markets、News、Agentic World、Fund Managers 视觉资产。

需要约束

  • 不是逐页像素级克隆，营销/账户/credits 页面降级为支撑页。
  • 实时行情和新闻用 mock/data adapter，不能硬编码抓取数值。
  • 移动端要主动修正原站小点击目标。
