B2 页面级设计与 MVP 范围

把 Fincept 的 14 个登录态入口重排为 Polymarket 自动交易终端。MVP 先做到可研究、可监控、可控制 paper bot。

F 键主路径
F1 Overview
bot mode, health, PnL, exposure, positions, orders
F2 Markets
market discovery, probability chart, order book, liquidity
F3 Signals
model score, agent consensus, evidence, edge explanation
F4 Risk
limits, approvals, exposure matrix, kill switch, skips
F5 News
TrendRadar/news feed, market impact, source freshness
F6 Data
OpenBB/public APIs/OSINT connectors, cache status
F7 Agents
event sentinels, research cycles, findings, dissent
F8 Audit
trades, signals, config changes, errors, replay
侧栏入口保留策略
Core

MVP 核心入口

Overview、Markets、Signals、Risk、Audit 必须可用，直接连接 paper bot 状态和 SQLite 记录。

Support

支撑入口

News、Data、Agents、Arena 使用 mock/adaptor 数据先形成体验，逐步接 TrendRadar、OpenBB、TradingAgents。

Defer

延后入口

Dataroom、Plans & Credits、Settings 保留 Fincept 结构，但 MVP 只做静态/配置占位。

MVP 验收标准

  • 1700x900 桌面 shell 高保真：顶部、ticker、左 rail、右 rail、底部状态栏。
  • 390x844 移动端无横向溢出，菜单抽屉可用，触控目标不小于 40px。
  • Overview 可显示 paper bot deployment、positions、trades、PnL、skips。
  • Markets 使用 lightweight-charts 显示概率/价格走势，并展示 order book 摘要。
  • Risk 所有控制动作必须确认，并写入审计事件。

明确不进 MVP

  • 不做真实资金 live trading。
  • 不做真实支付/credits 消耗闭环。
  • 不把所有外部项目一次性深度集成，只定义 adapter 边界。
  • 不逐字固定实时新闻、行情、价格和账户文本。
默认实现顺序

Shell -> mock data layer -> Overview -> Markets -> Signals -> Risk -> Audit -> News/Data/Agents/Arena placeholders -> mobile QA。
